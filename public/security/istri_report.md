\# istri セキュリティ強化報告書 (2026-04-05)



本プロジェクトにおいて、本番運用に耐えうるセキュリティの強化を実施しました。以下の通り、既知の脆弱性の修正と、潜在的なリスクへの対策が完了しています。



\---



\## 1. 認証・認可の強化 (Authentication \& Authorization)



\### 1.1 Firebase セキュリティルールの適用

\- \*\*旧状態\*\*: テストモード（誰でも全データの読み書き・削除が可能）

\- \*\*修正後\*\*: `request.auth != null` を必須とし、ログイン済みユーザーのみが操作可能なルールを適用。また、`/users/{userId}` においては本人以外の読み書きを禁止する設定に強化。



\### 1.2 パスワードのハッシュ化 (Hashing)

\- \*\*旧状態\*\*: ルームの合言葉（パスワード）が Firestore 上に平文（生テキスト）で保存されていた。

\- \*\*修正後\*\*: SHA-256 アルゴリズムを用いたハッシュ化を導入。Firestore 上には暗号化された文字列のみを保存し、データベースを直接覗かれても元のパスワードが漏洩しない設計に変更。



\---



\## 2. API エンドポイントの安全性 (Endpoint Security)



\### 2.1 パス・トラバーサル攻撃への対策

\- \*\*対象\*\*: `/api/image-proxy` 

\- \*\*修正\*\*: 外部からのパラメータ（`path`）に含まれる危険な文字列（`..`）を無効化。アクセス可能なディレクトリを `public` フォルダ内のみに限定し、サーバー内の重要ファイルが盗まれるリスクを解消。



\### 2.2 画像アップロードの制限と課金攻撃への対策

\- \*\*対象\*\*: `/api/upload` 

\- \*\*修正\*\*: 

&#x20; - ファイルサイズを \*\*1回あたり 5MB\*\* に制限。巨大ファイル送信によるストレージ容量の浪費や、課金（DoS）攻撃を防止。

&#x20; - 保存先を `/uploads` フォルダ以下に強制し、外部ディレクトリへの予期せぬ書き込みを防止。



\---



\## 3. ブラウザ・ネットワークレベルの保護 (Browser Security)



\### 3.1 セキュリティヘッダーの導入

\- `next.config.ts` に以下のヘッダーを追加：

&#x20; - `X-Frame-Options: DENY`: 悪意のあるサイトから自分のサイトを埋め込まれる（クリックジャッキング攻撃）のを防止。

&#x20; - `X-Content-Type-Options: nosniff`: ブラウザによる MIME タイプの誤認を利用した攻撃を防止。

&#x20; - `Referrer-Policy`: プライバシー保護のため、外部へのリファラ送信を制限。



\### 3.2 承認済みドメインの制限

\- Firebase Authentication にて、Vercel の公開ドメイン (`istri-nine.vercel.app`) のみを許可。不正なドメインからの認証リクエストを遮断。



\---



\## 4. 保守・パッケージ管理

\- `npm audit` を実行し、ライブラリの既知の脆弱性が \*\*「0件」\*\* であることを確認済み。



\---



\## 結論

以上の対策により、本アプリケーションは安全な本番運用が可能な状態となりました。今後も定期的な `npm update` と、ルーム ID にランダムな文字列を使用することを推奨します。
